# 复盘指南

## 为什么需要复盘

日志是原始素材：杂乱、带时间上下文、会随时间失去意义。
事实是提炼后的结论：简短、长期有效、可复用。

中间这一步压缩，就是复盘。它同时做三件事：

1. **提炼** —— 从当天日志里抽出长期有效的事实
2. **压缩** —— 把当天的过程压成一段保留因果的叙述
3. **清理** —— 清空原始日志，防止噪音堆积

## 谁来做

**当前会话的模型。** 不需要额外配 LLM——这是刻意的设计：
用一个独立的小模型做总结，质量通常不如你正在用的模型，而且要额外维护 key 和配置。

流程是两步：

```
consolidate_preview(day="today")   → 你拿到原始日志
   ↓（你自己读、想、提炼）
consolidate_apply(facts=[...], episodes=[...], purge=true)  → 提交
```

## preview 返回什么

```json
{
  "day": "2026-11-03",
  "log_count": 12,
  "logs": [{"id": "l_xxx", "at_iso": "...", "content": "...", "tags": []}],
  "existing_facts": [{"id": "f_xxx", "content": "...", "live": true}],
  "instructions": "..."
}
```

`existing_facts` 很重要——**先看它，避免把已有结论重复提取一遍**。
重复的事实会被 `consolidate_apply` 自动跳过，但你的 token 已经浪费了。

## 提炼事实的判断标准

从日志里挑，只有满足全部三条的才提：

1. 明天、下个月、明年都还成立
2. 一句话能说清，不需要"那天"这个上下文
3. 是结论，不是过程

```
日志："排查布局错乱，试了 ScaleWithScreenSize 无效，最后发现 anchor 被写死"
✅ 提取："预制体里的 RectTransform anchor 会被写死，改布局先检查它"
❌ 不提取："今天排查了布局错乱"        // 过程，不是结论
❌ 不提取："试了 ScaleWithScreenSize"   // 中间尝试，已被排除
```

**一般是 0~3 条。** 如果一天能提炼出 10 条"事实"，说明你的标准太松了——
那些八成还是日志级别的内容。

## 压缩经历

把当天的事写成 1~3 段叙述，保留**因果链**：

```
✅ "重构记忆库的存储层。先踩到 mcp 2.3 的 API 改名（FastMCP→MCPServer），
    又遇到 doctor 双连接死锁（DDL 未释放写锁）。最终确定双库三层结构，
    用触发器把 append-only 变成数据库层硬约束而不是应用层自觉。"
```

保留"先踩了什么坑、为什么这么定"——这是以后回看时最有价值的部分。
不要写成流水账（"上午做了 A，下午做了 B"），那和原始日志没区别。

如果当天没什么值得留的，`episodes` 传空数组也可以。**不要硬编**。

## 冲突处理

提炼出新事实，而旧事实与之矛盾时：

```json
{
  "content": "项目改用 UI Toolkit 做 UI",
  "invalidates": "f_旧事实的id"
}
```

旧的自动失效，指向新的。**不要**手工去删旧事实——历史是有价值的，
"曾经用 UGUI"这个信息在排查老问题时可能有用。

## purge 的取舍

- `purge=true`（默认）：原始日志物理清空。省空间、防噪音。
- `purge=false`：保留原始日志，只标记 `consolidated=1`。

什么时候用 `false`：复盘质量没把握，想先留着原始素材核对；
或者这一天有重要的原始记录（完整报错栈、精确时间线）值得留档。

注意：即使 `purge=false`，日志也已经被标记为已复盘，不会再出现在下次 preview 里。

## 节奏

- **每天一次**，在当天结束或第二天开始时
- 用自动化（定时任务）触发时，prompt 里写清楚：先 preview、再总结、再 apply
- 连着几天没复盘时，可以逐天补：`consolidate_preview(day="2026-11-01")`

## 什么不该做

- 不要把日志原文直接塞进 `episodes`（那是复制，不是压缩）
- 不要为了"显得有产出"而硬造事实
- 不要跳过 preview 直接 apply——你没有素材就没法总结
- 不要在 purge=true 之后后悔：原始日志删了就没了（`digests` 表里只留了 id 和统计）
